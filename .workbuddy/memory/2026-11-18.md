## SWAP 真分层实验（23:13-00:42）：解决"慢层无惩罚"失真
- 方案：放弃伪 NUMA 慢层（page cache 同速），改用 guest 真 swap（6GB /swapfile）——页被挤出 DRAM 落盘，重取走 major fault + virtio-blk，真实延迟。POC 实测换出页重取 118.8×慢（945ms vs 8ms，~29µs/页）。
- 拓扑：memcached membind=0（512MB DRAM 墙）+ -m 900 超分，448MB 工作集溢出进 swap；xTier 只管 node0 内的页（迁移已无意义，本实验 xTier 的角色退化为"谁留 DRAM"的放置决策——通过 promote/demote 与内核回收互动）。
- 结果（300s，800RPS）：
  none:  avg 2.77ms P99 6.75ms swp_in 319k swp_out 93k majflt 124k
  ML:    avg 2.69ms P99 8.19ms swp_in 306k swp_out 119k majflt 121k
  Random: avg 3.05ms P99 7.87ms swp_in 300k swp_out 119k majflt 111k
- 诚实结论：三组 swap 流量都 ~30 万页/300s，major fault 同量级——**xTier 的 demote 决策没有传导到 swap 放置**：内核回收自己选冷页，xTier 的 demote 目标（node1）已不存在（单节点），决策与 swap-out 不同频。差距只剩 ML avg 略优（2.69 vs none 2.77, random 3.05）在噪声边缘。
- 方法论结论（重要）：**swap 法正确制造了"换出惩罚"，但 xTier 的 demote 路径是"node0→node1 迁移"，不是"node0→swap"。两者语义不同——要 xTier 真正管理 swap 放置需要 demote 到一个"更慢的节点"，即恢复双节点但 node1 用 O_DIRECT 后端（绕宿主 cache）。这是下一步：QEMU 加 cache.direct=on 的 memory-backend-file。
- swap 实验数据已入 ledger（noneSW/mlSW/rndSW）。

## O_DIRECT 尝试与 swap 64MB 梯度（23:47-00:45）
- O_DIRECT 失败：QEMU 11 (macOS) 的 memory-backend-file 无 cache.direct 参数（Linux 版才有）；tierlat 实测 node0/node1 均 0.18µs/页（宿主 36GB page cache 吸收了整个 6GB 后端文件），慢层同速失真无法用参数修复。
- 换道：swap 方案加压——budget=64MB 梯度三组（ML/Random/none，membind=0 + -m 900 超分，512MB 墙 + swap）。
- 结果：三组全部同量级（majflt 127k/140k/125k，P99 6.94/7.27/7.01ms）——**swap 流量被内核回收主导（~30 万页/300s），xTier 的晋升/降级决策依然没有传导**：xTier 是 node0↔node1 迁移器，单节点 swap 场景下它的 demote 目标不存在，promote 名额被 swap-in 洪流淹没。
- 基础设施修复：systemd-tmpfiles-clean 定期清空 /tmp（之前"重启丢资产"的真凶之一）——已 mask；实验资产全部迁移到持久盘 /root/exp/（wrk2、脚本、ledger）。
- 终局判断：QEMU/macOS 环境无法制造"慢层有惩罚 + xTier 决策有效传导"同时成立的场景。两条等价结论：①性能数字必须真机（KVM+PEBS 或 Linux QEMU 带 cache.direct=on 的双节点）；②swap 实验测得的 118.8× 换出惩罚证明"缺页更慢"的物理现象可在 QEMU 复现，但 xTier 架构（NUMA 迁移器）与 swap 语义不匹配，这不是 xTier 的 bug 而是实验环境的架构错配。
