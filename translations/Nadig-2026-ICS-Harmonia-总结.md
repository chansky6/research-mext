# Harmonia 论文总结

**Harmonia: Enhancing Data Placement and Migration in Hybrid Storage Systems via Multi-Agent Reinforcement Learning**
Nadig, Arulchelvan, Bera, Shahroodi, Singh, Kakolyris, Yüksel, Sadrosadati, Park, Mutlu — ETH Zürich / AMD Research / POSTECH
ICS '26（arXiv:2503.20507v4）

> 完整中文翻译见同目录 `Nadig-2026-ICS-Harmonia-完整翻译.md`。
> **注意层次**：本文是**存储层**（SSD/HDD/PMEM 组成的 HSS），不是内存层（DRAM/CXL）。"页"指 4 KiB 存储页，不指物理内存页。

## 一句话

把"数据放哪"和"数据怎么搬"拆给两个 RL 智能体分别学、靠奖励互相牵制——单智能体干这两件事会被任务干扰拖垮（比最佳基线差 21.9%），拆开后反而比最强的单点技术好 29–39%，代价是 240 ns 推理 + 206 KiB DRAM。

## 问题：放置与迁移互相拆台

HSS 的性能由两条策略决定：**放置**（新写落到哪个设备）与**迁移**（把已存数据在设备间重组）。已有工作只优化其中之一：

| 类别 | 代表 | 缺陷 |
|---|---|---|
| 启发式放置 | CDE | 只按频率/请求尺寸判冷热，不看长期效果 |
| ML 放置 | Sibyl（RL） | 放置会学，**迁移仍是启发式**，且在关键路径上驱逐页 |
| ML 迁移 | K-SVM、RNN-HSS | 固定间隔批量迁移，精确但时机僵、尾延迟爆炸 |
| 组合体（本文构造） | Sibyl+K-SVM、Sibyl+RNN-HSS | **比 Sibyl 单独更差**：决策冲突 → 多余搬动 + 收敛变慢 |
| 单智能体联合 | SAPM（本文构造） | **比 Sibyl 差 21.9%（成本优先下 30.5%）** |

关键实证：最好的先前方案 Sibyl 的平均 I/O 延迟比 **Oracle**（掌握未来全部访问模式的理想策略）高 **100.4%（成本优先配置 176.2%）**。差距一半来自放置，一半来自那条从不学习的启发式迁移策略。

为什么单智能体不行——三项根本差异：

1. **作用对象**：放置决定"新数据写哪"，迁移决定"旧数据搬到哪"；
2. **目标**：放置要在关键路径上最小化单请求延迟，迁移要最大化长期性能；
3. **时间尺度**：放置同步、在关键路径上；迁移异步、在空闲期。

这正是 MARL 文献里的"任务相似度低 → 单智能体学习干扰"的教科书场景。

## 机制：两个异构智能体，一套共享状态

```
                 状态(7 维 / 32 bit)
   ┌──────────────────┴──────────────────┐
放置智能体                            迁移智能体
(关键路径, 即时奖励 1/L_t)            (后台, 延迟奖励 ΣP_migr / ΣL_i)
   │                                     │
   └──► 写请求落到 H / M / L 设备         └──► 迁移队列(10) → 空闲期搬页
```

**状态（32 位，7 个特征）**

| 特征 | 含义 | 桶数 | 位数 |
|---|---|---|---|
| `req_type` | 读/写 | 2 | 1 |
| `req_size` | 请求尺寸（按 4 KiB 页） | 8 | 3 |
| `acc_intr` | 同页两次访问之间的访问次数 | 64 | 8 |
| `acc_freq` | 页累计访问次数 | 64 | 8 |
| `fast_cap` | 快设备剩余空间 | 8 | 3 |
| `curr_dev` | 页当前所在设备 | 2 | 1 |
| `migr_intr` | 同页两次迁移之间的迁移次数 | 64 | 8 |

注意 `fast_cap`（容量感知）与 `migr_intr`（迁移稳定性）——这两个是相对 Sibyl 新增的、**专门为迁移协同服务**的特征。

**奖励设计是全文最讲究的部分**

- 放置：$R_{placement} = 1/L_t$（即时）。但**不贪婪**——快设备容量有限，过度使用会因排队、带宽争用、GC 反噬；把不重要数据放到慢设备是为延迟敏感请求留容量。
- 迁移：迁移 $x$ 个页后，用随后 $n$ 个请求的平均延迟做**延迟奖励** $R_{migration} = \sum P_{migr} / \sum L_i$（$n=50$，$x=10$）。延迟是因为：预取的页不会立刻被用，释放的容量只在下一次放置时才体现价值。
- 惩罚 $P_{migr}$ 与页的平均迁移/访问间隔成反比，专门压乒乓迁移。

**协调靠奖励耦合，不靠共享参数**：放置的奖励依赖迁移是否腾出了空间；迁移的奖励来自其迁移之后 $n$ 个放置的延迟。两者互为对方的反馈信号。消融结果：去掉协调（各优化各的）平均差 **26.7%（成本优先下 59.8%）**，读密集负载尤甚——因为迁移智能体不再主动预取。

**工程细节（值得抄的部分）**

| 项 | 取值 | 理由 |
|---|---|---|
| 网络 | 7–10–$N$，swish | 90 个 MAC；权重 16 位 |
| 训练/推理网络分离 | 每 1000 请求同步权重 | 把训练延迟移出关键路径 |
| RL 算法 | C51（分类式 DQN） | 学 Q 值分布，比标量 DQN 稳定 |
| 经验缓冲区 | 每智能体 1000 条（100 KiB） | 更大能覆盖更多模式但更占内存 |
| 迁移队列 | 10 | 队列 0 → 不迁移、性能崩；>50 → 条目过期 |
| 元数据表 | 32 位/条；DRAM 只留 0.1% 热点 | 其余刷到快设备 |
| 回退机制 | 运行时可禁用，回落 OS 默认策略 | 规避探索期随机决策 |

## 结果

真实系统：AMD Ryzen 7 2700G（8 核 3.5 GHz、16 GiB DDR4）；设备 = Optane P4800X（H）、Intel D3-S4510（M）、Seagate 1TB HDD（L）、ADATA SU630（LSSD）、RAMDisk 模拟 PMEM。25 个负载（20 个调参 + 5 个 Baleen 未见负载），数据足迹 ≈ 快设备容量的 50000 倍。

| 配置 | 相对 Sibyl（延迟） | 相对 Oracle | 备注 |
|---|---|---|---|
| 双设备·性能优先 | **−29.3%** | 比 Oracle 高 41.0% | 吞吐 +49.4% |
| 双设备·成本优先 | **−44.8%** | 比 Oracle 高 33.1% | 吞吐 **+136.7%** |
| 三设备 | **−38.9%** | — | 每增设备仅 +1.3 KiB、+40 ns |
| 四设备 | **−39.2%** | — | 读密集最多 −58.3% |
| 带 PMEM（RAMDisk 模拟） | −19.4% | 比 Oracle 高 28.0% | 增益最小，PMEM 容量受限 |
| 多程序（6 组） | −32.8%（成本优先 −25.3%） | 高 35.4%（54.7%） | mix6 八并发最好：−39.4% |
| 未见负载（Baleen×5） | −31.2%（−31.5%） | — | 证明泛化不靠调参 |

**其他维度**

- 尾延迟：99 分位 −32.3%、99.99 分位 −25.3%（vs Sibyl）。固定间隔批量迁移的 K-SVM/RNN-HSS 尾延迟极高。
- 写放大：Harmonia **1.44（1.54）** vs Sibyl 1.38（1.50）、RNN-HSS 1.09（1.07）——**比 Sibyl 略高**，作者归因于读密集负载里的主动预取。写密集负载下反而低（1.24 vs 读密集 1.80）。
- 开销：推理 240 ns（90 周期）、训练 53 µs/步（后台）、元数据采集 100 ns、表更新 1 µs；存储 6 KiB 网络 + 200 KiB 缓冲 + 50 B 队列 + 100 B 奖励。
- 收敛：前 5000 请求内收敛；负载相位切换后训练损失仅有小尖峰，**数百请求内重新收敛**。

## 论文自己划的边界

1. **写放大略升**：延迟收益是用稍高的 WA 换的（1.44 vs Sibyl 1.38），作者明说"轻微增加 WA 以换取显著延迟改善"；
2. **PMEM 是 RAMDisk 模拟**：该组数字只有结构性意义，绝对值不可外推；
3. **超参一次性离线调优**（交叉验证），虽在 5 个未见负载上验证了泛化，但"调参用了 20 个负载"这件事仍是外部有效性的弱点；
4. **单宿主、单 HSS**：多租户间仲裁、跨节点池化未涉及；
5. **替换目标需改状态/奖励**：寿命、公平性、QoS 只讨论了形式，未实现；
6. **探索期需回退**：靠"可运行时禁用"来规避随机决策的伤害——这其实是把冷启动问题交给运维。

## 我的判断

**最硬的贡献不是 29%，是那个 21.9% 的负结果。** SAPM（单智能体联合优化）比 Sibyl 差 21.9%/30.5%，"四种组合技术不如其成分"更狠——这是对"加个统一 RL 就能端到端最优"这类叙事的直接反证。论文用它把设计空间砍成"必须异构智能体 + 奖励耦合"，而不是"选个更强的模型"。

**对我们的直接启示。** 我们现在这套 xTier/nginx 实验里，**晋升与降级/驱逐是同一个策略的一条手臂**：A-bit 扫描判冷、MLP 判热、共用容量账本。Harmonia 的结论指向一个可检验的假设：这两件事的目标与时间尺度不同（晋升要抓毫秒级相位切换、降级要保守），合成一个决策器会互相拖累。他们给出的证据形态很容易复刻——**做一个"无协调"对照**（各自优化各自的局部目标，不共享容量反馈），差值就是协调的价值。我们已有的 `random`/`freq` 对照组抓不到这一点，因为它们改的是**排序质量**，不是**协调结构**。

**不能直接照搬的部分。** 存储层与内存层的延迟量级差 2–3 个数量级：Harmonia 每次迁移的代价是 ms 级 I/O 拷贝，可以用"空闲期批量搬"掩盖；内存层的 migrate 是 19 µs 级，掩盖窗口完全不同。此外他们的 `fast_cap` 是粗粒度 8 桶，在内存层需要更细的预算控制（我们已有 `XTIER_DRAM_BUDGET_MB` 的 Top-K 准入）。奖励式 $1/L_t$ 在存储层可用，因为延迟差异大；在 NUMA 1.25× 的场景里 $1/L_t$ 的信号几乎无区分度——**这恰好回到我们上一轮讨论的问题：没有真实延迟差，RL 奖励就没有梯度**。

**一句话定位**：Harmonia 是"策略分解"这一设计模式在存储层的严格证明——证明它不是为了工程清晰，而是性能上不可省；而它的收益大小取决于层间代价差，这一点在所有分层系统里通用。
